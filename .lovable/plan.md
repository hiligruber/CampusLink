
# שלב 2 — התראות מייל + פרופיל מורחב

## חלק א׳ — מייל למפרסם על הצטרפות לנסיעה

**זרימה:** משתמש לוחץ "Join Ride" → נוצר booking בסטטוס `pending` → נשלח מייל למפרסם הנסיעה למייל שהוא נרשם איתו (`profiles.email`) עם פרטי הנוסע ושני כפתורים: **אישור** / **דחייה**.

**תשתית מיילים:**
- שימוש בדומיין ברירת המחדל הזמני של Lovable (בלי הגדרות DNS)
- הקמת תשתית מיילים (תורים, retry, suppression)
- יצירת Edge Function `send-transactional-email` עם תבנית `ride-join-request`

**התבנית תכלול:**
- שם הנוסע + מייל ליצירת קשר
- פרטי הנסיעה (מוצא, יעד, תאריך/שעה)
- שני כפתורים: ✅ אישור הצטרפות / ❌ דחייה — לינקים שמובילים לדף בתוך האפליקציה (`/booking/:id/respond?action=accept|reject`) שמעדכן את ה-booking

**צד אפליקציה:**
- דף חדש `BookingResponse.tsx` — מאמת שהמשתמש מחובר ושהוא בעל הנסיעה, מעדכן `bookings.status` ל-`accepted` או `rejected`, מציג הודעת הצלחה
- ב-`RideCard.tsx` כשלוחצים Join → אחרי insert ה-booking, קריאה ל-`supabase.functions.invoke('send-transactional-email', ...)` עם פרטי הנוסע והנסיעה

## חלק ב׳ — עריכת פרופיל מורחב

**הרחבת טבלת `profiles`:**
- `avatar_url TEXT` — תמונת פרופיל
- `hobbies TEXT` — תחביבים/תחומי עניין
- `music_preference TEXT` — מוזיקה מועדפת / סגנון שיחה בנסיעה

**Storage:**
- יצירת bucket ציבורי `avatars` עם RLS — כל משתמש יכול להעלות/לעדכן/למחוק רק את התמונה שלו (לפי `auth.uid()` בנתיב הקובץ)

**צד אפליקציה:**
- עדכון `Profile.tsx`: כפתור "עריכת פרופיל" שפותח דיאלוג / ניווט לעמוד `EditProfile.tsx` חדש
- עמוד `EditProfile.tsx` עם:
  - העלאת תמונה (preview + upload ל-bucket)
  - שדה שם מלא
  - שדה תחביבים (textarea)
  - שדה מוזיקה/שיחה (textarea)
  - כפתור שמירה
- הצגת התמונה במקום המונוגרמה ב-`Profile.tsx` ובכרטיסי נסיעה (אם רוצים — אפשר גם להוסיף ל-`RideCard`)

## סדר ביצוע

1. הרחבת `profiles` + יצירת bucket `avatars` + RLS
2. עמוד עריכת פרופיל + העלאת תמונה
3. הקמת תשתית מיילים + סקפולד transactional
4. תבנית `ride-join-request` + שליחה אחרי Join
5. דף `BookingResponse` לטיפול באישור/דחייה דרך הלינק במייל
