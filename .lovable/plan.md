
# שלב 2 (מעודכן) — התראות בתוך האפליקציה במקום מייל

נדלג על שליחת מייל בשלב הזה (הגדרת דומיין מורכבת מדי כרגע) ונבנה מערכת התראות **בתוך האפליקציה** שעובדת מצוין למקרה הזה ולא דורשת שום הגדרה חיצונית.

## מה ייבנה

### 1. עמוד "ההזמנות שלי" / "בקשות לנסיעות שלי"
עמוד חדש `/bookings` שמציג למפרסם הנסיעה את כל הבקשות שהוא קיבל, ומציג לנוסע את הבקשות שלו ואת הסטטוס שלהן.

**מה רואים:**
- **בתור מפרסם נסיעה:** רשימת בקשות שהתקבלו, עם שם הנוסע, פרטי הנסיעה, וכפתורי **אישור** / **דחייה**.
- **בתור נוסע:** הבקשות שלך עם הסטטוס (ממתין / אושר / נדחה).

### 2. סמן התראה (badge אדום) בתחתית
על אייקון "Bookings" ב-`BottomNav` יוצג מספר אדום עם כמות הבקשות החדשות שמחכות לתגובה (רק למפרסם).

### 3. עדכון בזמן אמת
כשנוסע נרשם לנסיעה, המפרסם רואה את הבקשה מיד (Supabase Realtime על טבלת `bookings`).

### 4. RLS — תיקון קטן
לוודא שהמפרסם רואה את ה-`profiles.full_name` + `email` של הנוסע שביקש להצטרף, כך שיוכל לדעת מי זה ולתקשר איתו אם רוצה.

## למה זה עדיף ממייל כרגע

- עובד מיד, בלי הגדרת דומיין/DNS/SMTP
- כל התקשורת נשארת בתוך האפליקציה
- חוויה מודרנית כמו Bumble/BlaBlaCar
- כשנרצה — אפשר תמיד להוסיף מייל **בנוסף** מאוחר יותר (שלב 4)

## למה לא נעשה עכשיו

- שליחת מיילים — נחזור לזה אחרי שתחליטי על דומיין
- דירוגים — שלב 3 (כמתוכנן)

## פרטים טכניים

- נתיב חדש: `/bookings`
- קומפוננטה: `Bookings.tsx`
- שאילתות:
  - בקשות שהתקבלו: `bookings` JOIN `rides` WHERE `rides.driver_id = me`
  - הבקשות שלי: `bookings` WHERE `passenger_id = me`
- כפתורי אישור/דחייה: `UPDATE bookings SET status='accepted'/'rejected'` (ה-trigger הקיים `sync_available_seats` כבר ידאג להוריד מקום אוטומטית)
- Realtime: `supabase.channel().on('postgres_changes', ...)` על bookings
- Badge ב-BottomNav: `useQuery` שסופר `pending` עבור הנסיעות שלי
